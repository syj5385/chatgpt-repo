# FileServer 고급 기능

이 문서는 계정 기능 이후 추가된 파일 탐색기 기능과 저장 구조를 설명합니다.

## 저장 구조

실제 파일은 컨테이너 내부가 아니라 호스트의 `FileServer/files` 아래에 유지됩니다.

```text
FileServer/files/
├── users/
│   ├── admin/
│   ├── user01/
│   └── user02/
├── shared/
├── Trash/
│   ├── admin/
│   ├── user01/
│   └── user02/
├── .versions/     # 이전 파일 버전, 웹에서 직접 접근 불가
└── .uploads/      # 분할 업로드 임시 파일, 웹에서 직접 접근 불가
```

승인된 사용자 계정에는 다음 디렉터리가 자동 생성됩니다.

```text
files/users/<사용자 ID>
files/Trash/<사용자 ID>
```

일반 사용자는 자신의 개인 폴더, 자신의 휴지통, 공용 폴더만 접근할 수 있습니다. 관리자는 숨김 시스템 디렉터리를 제외한 전체 파일을 관리할 수 있습니다.

## 구현된 기능

### 개인 및 공용 저장공간

- 사용자별 개인 홈 폴더
- 사용자별 휴지통
- 모든 승인 사용자가 이용하는 `shared` 공용 폴더
- 관리자 전체 저장소 접근
- 서버 측 경로 권한 검사

### 파일 탐색기

- 목록 보기와 썸네일 그리드 보기
- 이미지 썸네일
- 이미지·동영상·오디오·PDF·텍스트 미리보기
- 텍스트 파일 편집
- 폴더 업로드
- 다중 선택
- 이동과 복사
- ZIP 생성
- ZIP/TAR 압축 해제
- 파일 및 폴더 크기 계산
- 라이트·다크·시스템 테마
- 모바일 반응형 화면

HTML, SVG, JavaScript, XML처럼 브라우저에서 능동적으로 실행될 수 있는 파일은 같은 origin에서 실행하지 않고 다운로드로 처리합니다.

### 검색과 분류

- 전체 저장소 검색
- 폴더·이미지·영상·문서·압축파일 필터
- 최소 파일 크기 필터
- 최근 사용 파일
- 즐겨찾기
- 태그
- 파일별 활동 기록
- 파일별 댓글
- SHA-256 정보 표시

### 버전 관리

파일을 덮어쓰기 전에 기존 파일을 `.versions` 아래에 보관합니다.

- 이전 버전 목록
- 이전 버전 다운로드
- 이전 버전 복구
- 파일별 기본 20개 버전 유지
- 오래된 버전 자동 정리

보관 개수는 다음 환경변수로 변경할 수 있습니다.

```env
FILESERVER_VERSION_LIMIT=20
```

### 대용량 업로드

- 8MiB 단위 분할 업로드
- 현재 페이지에서 일시정지와 재개
- 업로드 진행률
- 실패 상태 표시
- 취소 및 임시 파일 정리
- 같은 이름의 파일 덮어쓰기 확인
- 폴더 구조를 보존하는 폴더 선택 업로드

분할 크기:

```env
FILESERVER_UPLOAD_CHUNK_BYTES=8388608
```

브라우저를 완전히 종료하거나 파일 선택 권한을 잃은 뒤 자동 재개하는 기능은 아직 제공하지 않습니다. 현재 재개 기능은 같은 페이지 세션 안에서 동작합니다.

### 공유 링크

- 파일과 폴더 다운로드 공유
- 폴더는 ZIP으로 다운로드
- 비밀번호
- 만료일
- 다운로드 횟수 제한
- 링크 해제
- 폴더 업로드 전용 파일 제출 링크

공개 업로드 링크의 파일당 최대 크기 기본값은 2GiB입니다.

```env
FILESERVER_PUBLIC_UPLOAD_MAX_BYTES=2147483648
```

공유 링크의 최대 만료 기간:

```env
FILESERVER_SHARE_MAX_DAYS=90
```

### 파일 잠금

파일 상세 패널에서 파일을 잠글 수 있습니다.

- 기본 잠금 시간 1시간
- 잠근 사용자와 만료 시간 표시
- 잠금 소유자 또는 관리자만 해제
- 다른 사용자의 변경 요청은 HTTP 423으로 차단

### 저장 용량 관리

일반 사용자 기본 할당량은 50GiB입니다.

```env
FILESERVER_DEFAULT_QUOTA_BYTES=53687091200
```

관리자 페이지에서는 다음 정보를 확인하거나 변경할 수 있습니다.

- 전체 디스크 용량
- 사용 중인 용량
- 남은 용량
- 활성 공유 링크 수
- 사용자별 실제 사용량
- 사용자별 할당량

할당량을 `0`으로 설정하면 무제한입니다.

## 공개 모드

```env
FILESERVER_ACCESS_MODE=public
```

공개 모드에서는 로그인 화면 없이 파일 탐색기를 사용할 수 있습니다. 고급 파일 API를 위해 외부에 노출되지 않는 내부 시스템 계정과 세션이 자동 생성되지만, 해당 세션에는 관리자 계정 관리 권한이 없습니다.

공개 모드는 파일 읽기뿐 아니라 업로드·수정·삭제도 누구나 수행할 수 있으므로 신뢰할 수 있는 내부망에서만 사용해야 합니다.

## 실행과 검증

```bash
cd /Users/yyjun.song/workspace/FileServer
git pull
bash restart.sh
```

`restart.sh`는 다음 항목을 검사합니다.

1. Docker Compose 문법
2. 이미지 빌드
3. Python 구문 및 FastAPI 주요 라우트
4. Nginx 설정
5. 컨테이너 상태
6. HTTPS 인증 설정 API 응답

기본 주소:

```text
HTTP  : http://localhost:5080
HTTPS : https://localhost:5443
```

## 현재 제한사항

- 내부 사용자 한 명에게만 파일을 공유하는 세밀한 ACL은 아직 없으며, 내부 공용 파일은 `shared` 폴더를 사용합니다.
- PDF 첫 페이지와 동영상의 서버 생성 썸네일은 없으며, 이미지 파일만 즉시 썸네일로 표시됩니다.
- 완전한 콘텐츠 기반 중복 제거는 없고, 업로드 충돌은 파일명과 크기를 우선 사용합니다.
- 브라우저 재시작 후 업로드 자동 재개는 지원하지 않습니다.
- 대용량 폴더의 공유 ZIP은 메모리를 많이 사용할 수 있으므로 매우 큰 폴더는 미리 ZIP으로 만들어 공유하는 편이 안전합니다.
- 휴지통과 버전 파일의 기간 기반 자동 삭제 정책은 아직 없으며, 버전은 개수 기준으로 정리합니다.

- 백신 또는 YARA 기반 업로드 검사
- 사내 CA 설치 후 PyPI `trusted-host` 제거
